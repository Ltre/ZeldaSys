## 2. SVG 风格导入：首版确定规则

首版直接允许导入标准 `.svg` 文件，但只支持一个明确、有限、可验证的 SVG 子集。

首版目标支持：

- `path`
- `polygon`
- `rect`
- `circle`
- `ellipse`
- 闭合 fill 轮廓
- 孔洞

首版明确不把以下 SVG 能力作为实体几何输入：

- text
- filter
- mask
- clipPath
- animation
- script
- stroke 本身

对于 stroke，首版不把线宽自动解释成实体厚度；用户如果需要实体，应提供闭合轮廓。

导入过程：

`SVG -> 解析支持子集 -> 统一到内部 2D contour -> 规范化尺寸 -> 三角化 -> 挤出 -> render mesh -> collider`

导入 UI 至少需要用户确认 / 设置：

- 目标宽度；
- 目标高度；
- 挤出厚度。

SVG 原始单位不直接成为物理世界单位，导入后统一映射到 ZeldaSys 自己的尺寸体系。

内部持久化不应永久依赖原 SVG DOM。应保存标准化后的内部轮廓数据，同时可选保留原始 SVG 作为来源信息，以便后续重新编辑或重新导入。

## 3. 功能零件控制：首版确定规则

功能件至少包含：

- Wheel
- Motor
- Fan

### 3.1 通用控制

每个主动功能件具有：

- `enabled`
- 类型专属参数

用户进入“运行 / 模拟”状态后，所有 `enabled = true` 的装置开始工作。

首版不引入：

- 电池；
- 能量消耗；
- 电路布线；
- 复杂逻辑编程。

这些以后可以在功能件接口上扩展。

### 3.2 Motor

首版至少包含：

- enabled
- direction
- targetSpeed
- maxTorque

Motor 绑定旋转关节 / 轮轴，而不是通过每帧直接篡改 Transform 来制造假运动。

### 3.3 Fan

首版至少包含：

- enabled
- thrust
- localDirection

Fan 在模拟过程中沿自身局部方向持续施加物理力。

## 4. 编辑态与模拟态：首版确定规则

采用明确的双状态模型。

### 4.1 编辑态

目标是让用户稳定建造。

规则：

- 不启用会让作品自行下落的正常重力模拟；
- 用户可以选择、移动、旋转、连接、解除连接、删除、复制；
- 仍提供碰撞 / 穿透辅助；
- 不要求用户在物理抖动中完成精确装配。

### 4.2 进入模拟

点击“运行”时：

1. 保存当前 BuildDocument 的编辑快照；
2. 根据领域状态建立 / 激活完整物理世界；
3. 开启重力、碰撞、刚体、关节；
4. 启动 enabled 的功能件。

### 4.3 停止模拟

首版默认恢复运行前编辑快照。

模拟中的翻车、位移、跌落不会永久破坏用户原来的设计。

未来可以增加“保留模拟结果 / 将当前物理姿态应用到编辑器”，但不进入首版必需范围。

## 5. 任意表面粘合：首版确定规则

普通结构连接必须支持任意表面，而不是要求预设 Snap Point。

首版交互：

1. 用户抓取 source part；
2. 靠近 target part；
3. 系统寻找候选目标表面；
4. 显示接触点、表面方向和粘合预览；
5. 自动让 source 接触面与 target 接触面法线对齐；
6. 保留绕接触法线的旋转自由度；
7. 用户可在确认前调整该角度；
8. 用户确认；
9. 保存双方局部 anchor / orientation；
10. 创建固定物理约束。

连接需要吸附 / 粘合距离阈值，具体数值属于技术调试参数，不在需求层写死。

连接后需要有明显视觉表达，使用户一眼看出两个零件是否已经连接。该原则直接参考《王国之泪》中高可见度的连接反馈，但视觉设计必须使用 ZeldaSys 自己的原创表现。

## 6. 特殊连接

普通零件粘合：

- Fixed / Weld-like constraint

Wheel / Motor 等需要旋转的部件：

- Revolute / Hinge-like constraint

未来如果增加滑轨、活塞、弹簧、万向节，则继续扩展 Connection / Constraint 类型，不改变普通表面连接的数据基础。

## 7. 首版性能目标

典型建造规模仍为约 50 个零件。

技术验证必须覆盖至少：

- 约 50 个刚体；
- 多个普通固定连接；
- 多个旋转关节；
- 若干 Motor；
- 若干 Fan；
- 碰撞；
- 移动端渲染；
- 移动端编辑交互。

首版性能目标应围绕“典型 50 件作品稳定可用”，而不是追求上千零件。

## 8. 平台与服务端

首发验证：

- PWA
- Android

仍保持离线优先。

当前不需要 Node.js 服务端。

服务端只在账号、云同步、分享、公共素材库、多人协作等需求出现后进入范围。

## 10. 当前产品基线

> ZeldaSys 首版是一个 PWA / Android 优先、离线优先的 3D 物理建造沙盒。用户可以使用参数化零件或导入受限 SVG 矢量轮廓创建自定义零件，在任意表面位置粘合零件，并在“编辑态 / 模拟态”之间切换。模拟态提供实时重力、碰撞、刚体与约束，同时支持轮子、马达和风扇等主动功能件。典型作品规模约 50 个零件。
