# ZeldaSys 模块说明模板

> 用于新建模块级事实说明。尖括号中的项目需按证据填写；未核实的内容保留为“待核实”，不要把计划写成已实现事实。

## 文档基线

- 模块：`<模块名称>`
- 核对日期：`<YYYY-MM-DD>`
- 源码锚点：`<Git commit SHA>`
- 对应路线：`<roadmap 章节或需求文档>`

## 模块职责

说明该模块解决的用户问题、边界，以及它和 ZeldaSys 其它模块的关系。

## 当前实现

仅记录已能从源码或测试确认的行为，并链接到相关文件。

## 数据与调用流程

从用户操作开始，按实际调用顺序列出 UI、领域逻辑、几何 / 物理 runtime 和持久化之间的关系。注明哪一层拥有可保存的数据。

## 交互与失败路径

记录实际存在的交互、取消与错误反馈，以及相关平台差异。没有实现的行为标为“计划中”。

## 测试与回归风险

链接到现有测试，说明覆盖范围、未覆盖的重要情况和已知风险；不要声称未执行的验证已通过。

## 决策与历史

链接相关 QA 日志、Prompt、开发日志和替代方案。区分当前决定、历史方案与未来候选项。

## 未完成事项

按 roadmap 记录该模块尚未完成的验收项及其依赖。
